Building formulas with operators

In addition to feeding clauses directly to a SatProblem<T>, you can assemble a Boolean expression out of Literal<T>, Clause<T> and Formula<T> objects and pass it to the solver in one go. This is useful when the constraints come from another layer (e.g. a parser or a domain model) that wants to hand the solver a complete CNF expression.

Literals

A literal is a variable identity plus a negation flag. Any value that implements IEquatable<T> can be wrapped in a literal:

var a = Literal.Of("a");
var b = Literal.Of("b");
var notA = !a;            // negation

Any T is also implicitly convertible to Literal<T>, so you can usually just write the underlying value:

Literal<string> a = "a";

Clauses

A Clause<T> is a disjunction of literals (at least one must be true). Use the | operator to combine literals into a clause:

Clause<string> clause = a | b | !c;       // a ∨ b ∨ ¬c

A single literal is implicitly convertible to a unit clause:

Clause<string> fact = a;                   // {a}

Formulas

A Formula<T> is a conjunction of clauses (all must be true), i.e. a CNF expression. Use the & operator to combine clauses into a formula:

Formula<string> formula = (a | b) & (!a | c) & (!c | d) & a;

Handing a formula to the solver

SatProblem<T> accepts a Formula<T> via either AddFormula or the += operator:

var problem = new SatProblem<string>();
problem += (a | b) & (!a | c) & (!c | d) & a;

Model<string>? model = problem.Solve();

You do not need to call AddVariable first; any literal referenced in the formula will be registered on first use.

Inspecting and simplifying a formula

Formula<T> is a HashSet<Clause<T>>, so the usual set operations work. It also exposes a few helpers:

  • ContainsEmptyClause: true if any clause is empty, in which case the formula is trivially unsatisfiable.
  • IsConsistent: true if the formula is a set of non-conflicting unit clauses (i.e. already represents a concrete assignment).
  • GetLiterals: every literal referenced anywhere in the formula.
  • GetPureLiterals: literals that appear with only one polarity. These can always be set true without changing satisfiability.
  • Simplify: returns a new formula with unit propagation and pure-literal elimination applied to a fixed point.
Formula<string> simplified = formula.Simplify();
if (simplified.ContainsEmptyClause)
{
    // Unsatisfiable without even invoking the solver.
}

Simplification is purely a preprocessing convenience; the CDCL engine performs unit propagation internally during the search.
